# サーバーから使う API

アプリのサーバー（BFF）から、社員として Chat Note を読み書きする API です。

## しくみ

- アプリのサーバーが、**その社員のアクセストークン**を付けて呼びます。基盤の API を呼ぶときと同じトークンです。使えるのは、Chat Note の API を使うために登録したアプリの、サインインで発行されたアクセストークンだけです。ID トークンは使えません。
- Chat Note はトークンを確かめ、**その社員として**動きます。見える場所・書ける場所は、その社員の権限のままです。
- アプリのサーバーには、どの社員にもなりすませる共通の鍵は渡しません。
- その社員が Chat Note を一度も開いたことがなくても、この API を初めて呼んだときに、Chat Note の利用者が作られます。これでブラウザーが Chat Note にサインインするわけではありません。
- アクセストークンの期限は短い（数分）です。基盤の API と同じように、期限に合わせて更新して付け直してください。
- **API は、Chat Note と同じサーバーの中からだけ使えます。** インターネット側から呼ぶと、本文のない 404 が返ります。
- ブラウザーの `Origin` を転送すると、書き込みが `403`（`{"error":"Origin rejected"}`）で断られることがあります。

## 呼び方

| 項目 | 値 |
|---|---|
| つなぎ先 | アプリのサーバーから見た Chat Note の住所（環境ごとにお知らせします） |
| 前に付けるパス | `/server-api/v1` |
| 認証 | `Authorization: Bearer <その社員のアクセストークン>` |
| 送る形 | `Content-Type: application/json`（UTF-8）。1回の要求は1 MBまで |
| 送らないもの | ブラウザーの `Cookie` や `Origin` は転送しないでください |

## 操作の一覧

| 操作 | メソッドとパス | 送るもの | 返るもの |
|---|---|---|---|
| 自分の名前 | `GET /me` | — | `{"name": "山田 太郎"}` |
| 見られる場所の一覧 | `GET /places` | — | 下の例 |
| ケース番号から場所を取得する（なければ作る） | `GET /cases/<ケース番号>/place` | — | `{"place_id": 33, "open_url": "/case/A-1001"}` |
| 場所のスレッドの一覧 | `GET /places/<id>/threads?page=1` | — | 下の例 |
| 場所のノートの一覧 | `GET /places/<id>/notes?page=1` | — | 下の例 |
| スレッド・ノートの投稿を読む | `GET /threads/<id>?page=1` | — | 下の例 |
| スレッドを作る | `POST /places/<id>/threads` | `{"title": "…", "content": "…", "tags": []}` | `{"id": 45}` |
| ノートを作る | `POST /places/<id>/notes` | `{"title": "…", "content": "…", "tags": ["指示書"]}` | `{"id": 46}` |
| 返信する | `POST /threads/<id>/replies` | `{"content": "…"}` | `{"id": 1024}` |

- `GET /me` の `name` は、アクセストークンの名前を、Chat Note の決まりで整えたものです。Chat Note の画面の表示名と違うことがあります。社員を見分ける値には使わないでください。
- 「スレッドを作る」「ノートを作る」で返る `id` は、スレッド・ノートの番号です。「返信する」で返る `id` は、投稿の番号です。
- API で返信すると、スレッドへの書き足しになります。特定の投稿への返信にはならないので、画面の返信通知（鈴の印）には出ません。

### 場所の一覧

```json
{
  "places": [
    { "id": 13, "name": "部署", "parent_id": null, "kind": "departments" },
    { "id": 14, "name": "営業", "parent_id": 13, "kind": "department", "department": "営業" },
    { "id": 32, "name": "案件", "parent_id": null, "kind": "cases" },
    { "id": 33, "name": "A-1001 本社 改装", "parent_id": 32, "kind": "case", "case_number": "A-1001" }
  ]
}
```

| `kind` | 意味 |
|---|---|
| `department` | 部署の場所（`department` に部署の名前） |
| `case` | ケースの場所（`case_number` にケース番号） |
| `departments` / `cases` | それぞれの親 |
| `other` | そのほか |

自動で作るケースの場所の名前は、100文字を超える分を切り捨てます。

### スレッドとノートの一覧

```json
{
  "items": [
    { "id": 45, "title": "納期の確認", "posts": 3,
      "created_at": "2026-11-25T10:44:05.956Z", "last_post_at": "2026-11-25T11:02:10.120Z",
      "tags": [] }
  ],
  "page": 1,
  "pages": 1
}
```

- `page` は1からの整数です。1ページの件数は決まった値ではありません。`pages` を見て、続きを読んでください。
- スレッドの一覧にはノートが含まれません。そのため、途中のページが空でも、そのあとのページにスレッドがあることがあります。

### 投稿を読む

ノートも、同じ `/threads/<id>` で読みます。

```json
{
  "id": 45, "title": "納期の確認", "place_id": 33, "page": 1, "pages": 1,
  "posts": [
    { "id": 1023, "author": "山田 太郎", "created_at": "2026-11-25T10:44:05.956Z",
      "html": "<p>来週の火曜に出荷できますか。</p>" }
  ]
}
```

- `open_url` と、`html` の中の `/` で始まるリンク・添付の URL は、Chat Note の住所を前に付けて使ってください。`https://` で始まるものは、そのまま使います。はめ込むときは `?logo=off` を足してください。
- 添付を表示するには、ブラウザーでも Chat Note にサインインしていて、その場所を見られることが必要です。

## 書くときの決まり

| 項目 | 決まり |
|---|---|
| 本文（`content`） | Markdown で書けます（見出し・表・箇条書き）。返る `html` は、表示用に整えたものです |
| 件名（`title`） | 1〜255文字（必須） |
| 本文の長さ | 1〜32,767文字（必須） |
| 札（`tags`） | 1つ3〜15文字。1件に付けられる札の数は、初めの設定では5つまでです。管理画面で変えられます（[管理画面での設定](admin.md)）。ノートは「ノート」の印に1つ使うので、付けられる札は1つ少なくなります |
| 札の整え方 | 英字は小文字にそろえられます（例：「WEB向け」は「web向け」）。記号は取り除かれ、15文字を超える分は切られ、短すぎる札は付きません。`chat-note` は印として予約しています。`chat-note` と、整えると `chat-note` になる札（前後の空白や記号が付いたもの）は送らないでください |
| 札での絞り込み | 一覧を札で絞る指定はありません。一覧の `tags` を見て、アプリの側で絞ってください |
| 添付ファイル | API では送れません。Chat Note の画面から添付してください |

## エラー

応答は `{"error": "<code>"}` の形です。

| 状態 | `error` | 意味 |
|---|---|---|
| 400 | `bad_request` `bad_case_number` `bad_place` `bad_thread` | 送ったものの形・中身が決まりに合わない（件名や本文の長さ、札の数を含む） |
| 400 | `bad_json` | JSON の形が崩れている |
| 413 | `too_large` | 1 MBを超えている |
| 401 | `invalid_token` | トークンがない・期限切れ・使えないアプリのもの |
| 403 | `forbidden` | その社員には、その場所・ケースの権限がない |
| 403 | `no_email` | サインインにメールアドレスが登録されていない社員 |
| 404 | `not_found` | その場所・スレッドがない（または見えない） |
| 502 | `chat_note_error` | Chat Note の中で失敗した、または時間切れ。読む操作は、少し待ってやり直してください |

Chat Note の中の処理は、1回ごとに30秒で時間切れになります。1回の API の呼び出しの中で何回か処理するので、応答まで30秒を超えることがあります。呼ぶ側の待ち時間は、長め（たとえば90秒）にしてください。

**書き込む操作（スレッドを作る・ノートを作る・返信する）は、502 のときに自動でやり直さないでください。** 書き込みは済んでいて、応答だけが失敗したことがあります。一覧を読み直して、できているかを確かめてから、やり直してください。

## 変わったことを知る

Chat Note からアプリへ知らせを送る仕組み（Webhook）はありません。新しい書き込みを知りたい場合は、スレッドの一覧とノートの一覧の、各項目の `last_post_at` を、数分おきに読んでください。社員が画面を開いているときだけ読む形にすると、サーバーの負荷が少なく済みます。

## API の変更

API の形を変えるときは、前もってお知らせします。パスの `v1` は、今のアプリがそのままでは動かなくなる変更のときに上げます。
