# サーバー用 API

アプリのサーバー（BFF）から、社員として Chat Note を読み書きするための API です。API では、カテゴリを `place` と表します。

## 概要

- アプリのサーバーは、その社員のアクセストークンを付けて API を呼びます。基盤の API を呼ぶときと同じトークンです。使えるのは、Chat Note の API を使うために登録したアプリのサインインで発行されたアクセストークンだけです。ID トークンは使えません。
- Chat Note はトークンを検証し、その社員として処理します。閲覧・投稿できるカテゴリは、その社員の権限と同じです。
- アプリのサーバーには、すべての社員として操作できる共通の鍵は発行しません。
- 社員が一度も Chat Note を開いていなくても、この API を初めて呼んだときに、Chat Note のユーザーが作成されます。ブラウザーで Chat Note にサインインした状態にはなりません。
- アクセストークンの有効期限は数分です。基盤の API と同じように、期限に合わせて更新してください。
- この API は、Chat Note と同じサーバーの中からだけ使えます。インターネットから呼ぶと、本文のない 404 が返ります。
- リクエストにブラウザーの `Origin` ヘッダーが含まれていると、書き込みは `403`（`{"error":"Origin rejected"}`）になります。

## リクエストの形式

| 項目 | 値 |
|---|---|
| 接続先 | アプリのサーバーから見た Chat Note の URL（環境ごとにお知らせします） |
| パスの接頭辞 | `/server-api/v1` |
| 認証 | `Authorization: Bearer <その社員のアクセストークン>` |
| 本文の形式 | `Content-Type: application/json`（UTF-8）。1回のリクエストは1 MBまで |
| 転送しないヘッダー | ブラウザーの `Cookie` と `Origin` |

## 操作一覧

| 操作 | メソッドとパス | リクエスト本文 | レスポンス |
|---|---|---|---|
| 自分の名前を取得する | `GET /me` | — | `{"name": "山田 太郎"}` |
| 閲覧できるカテゴリの一覧を取得する | `GET /places` | — | 下の例 |
| ケース番号からカテゴリを取得する（なければ作成） | `GET /cases/<ケース番号>/place` | — | `{"place_id": 33, "open_url": "/case/A-1001"}` |
| カテゴリのスレッドの一覧を取得する | `GET /places/<id>/threads?page=1` | — | 下の例 |
| カテゴリのノートの一覧を取得する | `GET /places/<id>/notes?page=1` | — | 下の例 |
| スレッド・ノートの投稿を取得する | `GET /threads/<id>?page=1` | — | 下の例 |
| スレッドを作成する | `POST /places/<id>/threads` | `{"title": "…", "content": "…", "tags": []}` | `{"id": 45}` |
| ノートを作成する | `POST /places/<id>/notes` | `{"title": "…", "content": "…", "tags": ["指示書"]}` | `{"id": 46}` |
| 返信する | `POST /threads/<id>/replies` | `{"content": "…"}` | `{"id": 1024}` |

※ `GET /me` の `name` は、アクセストークンの名前を Chat Note の規則で整えたものです。画面の表示名と異なる場合があります。社員の識別には使わないでください。
※ スレッドとノートの作成で返る `id` はスレッド・ノートの番号、返信で返る `id` は投稿の番号です。
※ API で返信すると、スレッドへの追加の投稿になります。特定の投稿への返信にはならないため、画面の返信通知（ベルのアイコン）には表示されません。

### カテゴリの一覧の例

```json
{
  "places": [
    { "id": 13, "name": "部署", "parent_id": null, "kind": "departments" },
    { "id": 14, "name": "営業", "parent_id": 13, "kind": "department", "department": "営業" },
    { "id": 32, "name": "案件", "parent_id": null, "kind": "cases" },
    { "id": 33, "name": "A-1001 本社 改装", "parent_id": 32, "kind": "case", "case_number": "A-1001" }
  ]
}
```

| `kind` | 意味 |
|---|---|
| `department` | 部署のカテゴリ（`department` に部署名） |
| `case` | ケースのカテゴリ（`case_number` にケース番号） |
| `departments` / `cases` | それぞれの親カテゴリ |
| `other` | その他のカテゴリ |

※ 自動で作成するケースのカテゴリ名は、100文字を超える部分を切り捨てます。

### スレッドとノートの一覧の例

```json
{
  "items": [
    { "id": 45, "title": "納期の確認", "posts": 3,
      "created_at": "2026-11-25T10:44:05.956Z", "last_post_at": "2026-11-25T11:02:10.120Z",
      "tags": [] }
  ],
  "page": 1,
  "pages": 1
}
```

※ `page` は1から始まる整数です。1ページの件数は固定ではありません。`pages` を見て続きを取得してください。
※ スレッドの一覧にはノートが含まれません。そのため、途中のページが空でも、後のページにスレッドがある場合があります。

### 投稿の例

ノートも同じ `/threads/<id>` で取得します。

```json
{
  "id": 45, "title": "納期の確認", "place_id": 33, "page": 1, "pages": 1,
  "posts": [
    { "id": 1023, "author": "山田 太郎", "created_at": "2026-11-25T10:44:05.956Z",
      "html": "<p>来週の火曜に出荷できますか。</p>" }
  ]
}
```

※ `open_url`（ケース番号からカテゴリを取得する操作で返ります）と、`html` の中の `/` で始まるリンク・添付の URL は、Chat Note の URL を前に付けて使ってください。`https://` で始まるものはそのまま使います。埋め込む場合は `?logo=off` を付けてください。
※ 添付を表示するには、ブラウザーでも Chat Note にサインインし、そのカテゴリの閲覧権限を持っている必要があります。

## 入力の制限

| 項目 | 制限 |
|---|---|
| 本文（`content`） | Markdown で記述できます（見出し・表・箇条書き）。レスポンスの `html` は表示用に整えたものです |
| 件名（`title`） | 1〜255文字（必須） |
| 本文の長さ | 1〜32,767文字（必須） |
| タグ（`tags`） | 1つ3〜15文字。1件に付けられるタグの数は、初期設定では5つまでです。管理画面で変更できます（[管理画面での設定](admin.html)）。ノートには目印のタグが1つ自動で付くため、付けられるタグは1つ少なくなります |
| タグの整形 | 英字は小文字になります（例：「WEB向け」は「web向け」）。記号は削除され、15文字を超える部分は切り捨てられ、短すぎるタグは付きません。`chat-note` は目印として予約しています。`chat-note` と、整形すると `chat-note` になるタグ（前後の空白や記号が付いたもの）は送らないでください |
| タグでの絞り込み | 一覧をタグで絞り込む指定はありません。一覧の `tags` を見て、アプリ側で絞り込んでください |
| 添付ファイル | API では送れません。Chat Note の画面から添付してください |

## エラー

レスポンスは `{"error": "<code>"}` の形式です。

| ステータス | `error` | 意味 |
|---|---|---|
| 400 | `bad_request` | 送信した内容が制限に合っていない（件名や本文の長さ、タグの数を含む） |
| 400 | `bad_case_number` `bad_place` `bad_thread` | ケース番号、カテゴリの番号、スレッドの番号の形式が正しくない |
| 400 | `bad_json` | JSON の形式が正しくない |
| 413 | `too_large` | 1 MBを超えている |
| 401 | `invalid_token` | トークンがない、期限切れ、または対象外のアプリのトークン |
| 403 | `forbidden` | その社員に、そのカテゴリ・ケースの権限がない |
| 403 | `no_email` | サインインにメールアドレスが登録されていない社員 |
| 404 | `not_found` | そのカテゴリ・スレッドがない（または閲覧できない） |
| 502 | `chat_note_error` | Chat Note の内部で失敗した、またはタイムアウトした。読み取りの操作は、少し待ってから再実行してください |

Chat Note の内部処理は、1回ごとに30秒でタイムアウトします。1回の API 呼び出しで内部処理を複数回行うため、応答まで30秒を超えることがあります。呼び出し側のタイムアウトは長め（例：90秒）に設定してください。

書き込みの操作（スレッドの作成・ノートの作成・返信）は、502 のときに自動で再実行しないでください。書き込みは完了していて、応答だけが失敗している場合があります。スレッドとノートはカテゴリの一覧を取得し直して同じ件名のものがないかを、返信はスレッドの投稿を取得し直して、作成済みかを確認してから再実行してください。

## 更新の検知

Chat Note からアプリへ通知する仕組み（Webhook）はありません。新しい書き込みを検知するには、対象のカテゴリのスレッドの一覧とノートの一覧を数分おきに取得し、`last_post_at` が前回より新しい項目を確認してください。社員が画面を開いているときだけ取得すると、サーバーの負荷を抑えられます。

## API の変更

API の形式を変更する場合は、事前にお知らせします。パスの `v1` は、既存のアプリが動かなくなる変更のときに上げます。
