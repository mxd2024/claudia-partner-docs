# 競合・再送・復帰

更新が競合したとき、通信が途切れたときに、結果を正しく確認し、安全に復帰する方法です。

## 結果が不明なとき

タイムアウト、接続の断、`OUTCOME_UNKNOWN`は、操作が実行されなかったことの証明ではありません。

1. 対象、本文、期待する版、`Idempotency-Key`を保持します。
2. 同じ操作の照会、または、同じ内容の再送で、確定した結果を確認します。
3. 結果が分かるまで、別のキーで、同じ操作をもう一度実行しません。

操作ごとの確認の方法は、次のとおりです。

| 操作 | 確認の方法 |
| --- | --- |
| MCPの取込 | `imports_status`で、計画の状態を確認する |
| アプリの適用 | 同じfingerprintと、同じキーで再送する |
| 行の更新・削除 | 同じキーと本文で再送し、現在の行の版を確認する |

権限が失効した後など、確認できないときは、環境管理者に問い合わせてください。

## 412（版の競合）

412 `VERSION_CONFLICT`は、期待した版と、現在の版が一致しないことを示します。

1. 現在の権限で、対象を再取得します。
2. 最新の値と、利用者の変更を比較します。
3. 利用者が解決した、新しい操作にだけ、新しい`Idempotency-Key`を付けます。

期待する版だけを、自動で置き換えて、上書きしないでください。行が削除された、または見えなくなっているときは、404または403として扱います。

## 認証の期限切れ・失効

- 401で、トークンの期限切れなら、更新または再ログインを行います。無制限に更新を繰り返しません。
- 失効や、期限切れが続くときは、本人の再ログインへ戻ります。
- 403では、認可を広げようとせず、必要なMFAまたは管理者の確認へ案内します。

## 再送のときの権限

認証の切れや、権限の変更があっても、再送のときは、その時点の権限で評価されます。

詳しい再送の方式は、[共通ルール](https://mxd2024.github.io/claudia-partner-docs/v0.7/concepts.html)。エラーの一覧は、[エラーと再試行](https://mxd2024.github.io/claudia-partner-docs/v0.7/errors.html)。
