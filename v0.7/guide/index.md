# 基盤の全体像

**読み手**: Claudia Partner を導入する、お客様の経営者・担当者・開発者。
**このページで分かること**: Claudia Partner の基盤が、何を提供し、顧客アプリと、どう役割を分けているか。
**次に確認すること**: 接続の手順とAPIの仕様は、後のページで確認できます。

## 背景と考え方

Claudia Partner は、共通の基盤と、顧客アプリで構成されます。基盤とは、ログイン、権限、データなどの、共通のサービスのことです。顧客アプリとは、お客様の業務のために作る、アプリのことです。API上の`app`（アプリ定義）とは区別します。詳しくは[用語集](../glossary.html#section-2)を参照してください。基盤は、お客様の複数のアプリで、共通に使います。

- **共通にする部分と、お客様ごとに作る部分を、分ける**: ログイン、権限、データの保管は、間違えると影響が大きい部分なので、共通の基盤に集めます。業務の画面や手順は、お客様ごとに、顧客アプリで作ります。
- **権限は、リクエストのたびに、判断する**: 誰が、何を使えるかは、利用者が操作するたびに、基盤が判断します。アプリやAIは、基盤から許可された範囲で操作します。
- **利用環境の条件を確認する**: 接続先と有効な機能は、利用環境ごとに異なります。APIの版、権限、データの保持条件を確認してから、アプリを接続します。

## 全体像

基盤は、サービスを使うための入口を、2つ提供します。アプリ向けの基盤API（プログラムがサービスを呼び出す入口）と、AI向けのMCP（AIが外部のサービスを使うための、共通の接続方式）です。

```text
利用者 --(画面を使う)--> 顧客アプリ --(基盤API)--> [ Claudia Partner 基盤 ] --(原本を参照)--> 外部ストア（Dropboxなど。利用する場合）
AIエージェント --(MCP)--> [ Claudia Partner 基盤 ]
```

## 構成要素と通信

```text
[お客様の側：顧客アプリ]
  ブラウザ（対応条件を確認） --(1 画面を開く)--> 顧客アプリの入口（HTTPS・アプリのURL）
    --> アプリサーバー（配置先：利用条件に合わせて選択。画面の配信・BFF（アプリ用バックエンド）・業務サービス）
  AIエージェント（AIが利用者を助ける）
[Claudia Partner 基盤]
  入口: 基盤API（接続先は利用環境ごとに確認）／ MCP（取込用8ツール）    ← アプリサーバーは、暗号化された接続経路で基盤APIを呼ぶ（2）。AIエージェントは MCP を使う
  SSO・MFAと、リクエストごとの認証・認可（3）
  利用環境で有効な共通サービス：
    認証・認可（3） / データ（4：表と行の保管、作成・取得・更新・削除） / アプリ定義の管理（4：登録・更新・停止） / メディア（5：画像・PDFの参照）
  メディアは、管理された原本と、外部ストアの原本への参照を扱う（5）
```

1. **画面を開く**: ブラウザは、専用URLの入口を通って、アプリサーバーから、画面を受け取ります。アプリサーバーは、画面を配信し、業務サービスを動かし、基盤との間を、BFF（アプリ用のバックエンド）でつなぎます。
2. **基盤の入口を使う**: アプリサーバーは、暗号化された接続経路で、基盤APIを呼びます。AIエージェントは、基盤のMCPを使います。現在のMCPは、取込用の8ツールで、手元のMCPアダプターから、管理サイトの取込APIを経由して使います。全サービスのMCPは、準備中です。
3. **認証・認可**: 基盤は、[SSOとMFA](../glossary.html#section-3)で、利用者を確かめます（認証）。リクエストのたびに、使ってよい範囲かを判断します（認可）。
4. **データとアプリ定義**: 表と行を保管し、読み書きできるようにします。アプリ定義（顧客アプリが使うデータと権限の登録）の、更新と停止も行います。
5. **メディアの参照**: 管理された原本、または外部ストアにある原本への参照を扱います。[外部ストア](../glossary.html#section-4)とDropbox連携の利用条件は、利用環境ごとに確認します。

## 基盤が提供するサービス

- **認証・認可**: 利用者を確かめ（認証）、リクエストのたびに、使ってよい範囲かを判断します（認可）。
- **データ**: 表と行を保管し、作成・取得・更新・削除ができます。変更の履歴も残ります。
- **メディア**: 画像やPDFなどのファイルを扱います。管理された原本と、外部原本への参照を扱います。外部ストアは、利用環境で有効な場合に使えます。
- **アプリ定義の管理**: 顧客アプリが使うデータと権限を、アプリ定義として登録します。更新と、停止もできます。

## 役割の分担

- **お客様（画面・業務ロジック・接続資格を管理）**: 顧客アプリのOSと配置先は、開発者が利用条件に合わせて選びます。接続のための資格（アクセストークン）の安全な保管と、APIの仕様を守ることを担います。外部原本の保管・バックアップの範囲は、保存先の運用条件で確認します。
- **Claudia Partnerの運営側（API・認可・データベース・基盤の運用を管理）**: 共通サービスを管理します。具体的な運用範囲は、利用環境の取り決めに従います。
