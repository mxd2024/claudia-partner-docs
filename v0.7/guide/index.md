# アプリ開発の全体像

Claudia PartnerのCore APIを使い、あなたの業務に合うアプリを作るためのガイドです。画面と業務ロジックは顧客アプリに、認証・認可とデータ操作の契約は共通サービスに分けます。

この文書の対象は **API 0.7.0-experimental / 2026-10-07の固定公開契約**です。ブランチの先頭や、このサイトの更新日が稼働サービスの版を示すわけではありません。接続先・有効な機能・権限は環境管理者から受け取ります。

## 顧客アプリと共通サービスの関係

```text
利用者のブラウザー
  ├─ 画面・セッション ─→ 顧客アプリのBFF（あなたのサーバー）
  │                        └─ アクセストークン付き要求 ─→ Core API（環境ごとのHTTPS origin）
  └─ ログイン・MFA ─→ 認証サービス（環境ごとのissuer） ─→ 登録済みのBFF戻り先

サーバーの定期処理 ── service専用の資格 ──→ 許可されたCore API（環境ごとのHTTPS origin）
AIエージェント ── 取込MCPアダプター ──→ 管理アプリの取込API
```

認証サービスは利用者を確認してトークンを発行します。Core APIはそのトークンと、要求時点の権限・版・操作条件を確認します。顧客アプリのBFFはトークンをサーバーで保管し、画面に必要なデータへ整えます。ブラウザーへアクセストークンや機械の秘密鍵を渡しません。

このサイトは文書の配信だけを行います。ログインやAPIの実行は、あなたのアプリと、環境管理者が案内した接続先で行います。

## あなたが作るもの

| 顧客アプリ側 | 共通サービス側 |
| --- | --- |
| 業務画面、画面の状態、入力の確認 | 認証サービスでのログイン・MFA |
| BFF、セッション、トークンの安全な保管 | 要求ごとの認可と公開API契約 |
| 業務ロジック、利用者へのエラー表示 | 表・行、アプリ定義、履歴などの操作 |
| 競合・通信断からの復帰、運用手順 | 環境で有効化されたメディア・機能 |

アプリの配置先は契約と運用条件に合わせて決めます。特定のVPS、顧客別の専用サーバー、Dropboxの導入を、すべてのアプリの必須条件にはしません。

## 3つの接続を区別する

| 接続の主体 | 資格と入口 | 最初に読む |
| --- | --- | --- |
| 人の利用者 | OIDC Authorization Code + PKCE。BFFが利用者のaccess_tokenでCore APIへ接続 | [利用者として接続](../authentication.html) |
| 人の操作なしで動く処理 | 管理者の承認を受けたservice。登録した鍵による機械専用の資格 | [serviceとして接続](../service-access.html) |
| AIによるCSV取込 | 取込MCPアダプターと管理アプリの接続キー。Core APIのOIDC資格とは別 | [MCPの導入と範囲](../mcp.html) |

文書対象版のMCPは取込用8ツールです。134のCore API操作をすべてMCPで利用できるという意味ではありません。全サービスMCPは、対象版では準備中です。新しいアダプターや別版の動作を、この版の提供状況へ混ぜません。

## 機能を選ぶ

- 表と行を読む・更新する: [表とデータ](../tables.html)、[共通ルール](../concepts.html)。
- アプリ定義を登録する: [アプリの登録と運用](../tutorial.html)。
- 画像や添付を表示する: [メディア](../media.html)。managed_originalとexternal_referenceを区別し、外部ストアは環境で使えるものだけを選びます。
- 競合や結果不明から復帰する: [競合・再送・復帰](../reliability.html)。
- AIからCSVを取り込む: [MCPの導入](../mcp.html)、[対応範囲](../mcp-support.html)。

## アプリ用BFFの提供状態

アプリごとの利用者用クライアント登録・接続は [準備中] です。環境管理者が個別に案内し、自己登録画面・APIは [未提供]。開発用redirect_uriは [環境による]。接続先やクライアントを構成図から決めず、[接続依頼](../request-access.html)で確認してください。

## 開発を始める

まず[接続準備と最初の読取](../quickstart.html)で接続情報と機能の有効化を確認します。[架空の業務メモアプリ](../sample-app.html)で画面・BFF・APIの分担を読み、実装時は[APIリファレンス](../api.html)の操作別契約を確認してください。
