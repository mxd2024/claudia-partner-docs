# 接続情報を依頼する

基盤に接続するには、環境ごとの情報が必要です。これらを、このサイトから推測せず、環境管理者から受け取ります。

## 受け取る情報

| 項目 | 内容 | 使う場面 |
| --- | --- | --- |
| 基盤 | HTTPS origin、API版、有効な機能 | すべての呼び出し |
| 認証サービス | issuer、認証方式、必要なMFA | ログイン、トークンの取得 |
| 本人用のクライアント | 登録済みのclient_id、redirect_uri、scope | 本人としての接続 |
| 本人 | ログイン方法、利用する組織、必要な表の権限 | 本人としての接続 |
| 検証用の表 | collection、現在のschema_version、許可する操作、検証用の行 | 最初の読み書き |
| 証明書 | 公開の認証局、または管理者が交付した検証用の証明書 | TLSの検証 |

基盤のURL、アプリのURL、認証サービスのURLは、それぞれ別です。このサイトは、仕様の配信先であり、APIのサーバーではありません。

## 依頼する

開発・検証用の接続は、環境管理者が受け付けます。受付の手段は、メールです。

**現在の受付メール：morita@meta-xdesign.com**

一次回答は、**受信の翌営業日までを目標**とします。保証付きのSLAではありません。一次回答は、受付の確認、不足している情報の確認、対応の見込みの連絡です。接続情報の発行の完了を意味しません。利用の開始日は、申請の内容を確認した後に回答します。

### 依頼メールの雛形

```text
件名：【開発接続申請】環境名／利用目的

依頼者・所属：
返信先：
対象環境（不明なら用途を記載）：
利用目的：
利用区分：本人 / service / MCPの取込（管理サイトのアカウント）
必要な表・操作（閲覧、登録、更新など）：
利用開始希望日・利用終了日：
検証用データの希望：
登録済みclient_id（ある場合）：
redirect_uri（本人用クライアントを新規登録する場合）：
補足：
```

パスワード、アクセストークン、リフレッシュトークン、秘密鍵、cookieは、依頼のメールに書かないでください。接続先、設定、資格の渡し方は、本人と許可の範囲を確認して案内します。

## 受け取った後に確認すること

- 基盤のURLが、HTTPSである。
- 受け取ったclient_idとredirect_uriが、ログインの設定と一致している。
- 検証用の表の名前と、許可される操作が分かっている。

次は、[本人として接続する](https://mxd2024.github.io/claudia-partner-docs/v0.7/authentication.html)、または[serviceとして接続する](https://mxd2024.github.io/claudia-partner-docs/v0.7/service-access.html)へ進みます。
