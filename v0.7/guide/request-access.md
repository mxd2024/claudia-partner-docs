# 接続情報を依頼する

基盤、顧客アプリのBFF、認証サービス、管理サイトは、それぞれ別の接続先です。HTTPS originは環境ごとに受け取り、このサイトのURLや構成図から推測しません。

## 受付と現在の提供状況

接続の相談・文書の質問は、[公開GitHub Issues](https://github.com/mxd2024/claudia-partner-docs/issues)で受け付けます。顧客のClaude等から確認事項を整理して起票する場合も、公開情報だけを記載してください。公開窓口は相談と調整の入口です。実際の接続先・資格・顧客別設定は、環境管理者が確認した非公開の受渡し方法で交付します。

アプリごとの利用者用クライアント登録・接続は **[準備中]**。申請を受けて環境管理者が個別に案内する形で、登録画面・自己登録APIは **[未提供]** です。申請だけで利用可能になるとは限りません。開発用ループバックのredirect_uriは **[環境による]** ため、利用可能なURIと条件を登録前に確認します。受付時間、回答期限、SLAは未確定です。

開発端末（Mac）と本番（VPS等）の戻り先を併存登録し、同じアプリコード・認証方式で設定を切り替える移行は設計要件で、提供状態は [準備中] です。公開CAで検証できるCore・IdP入口を交付し、顧客のMacへSSH転送・独自CA登録を要求しないことを確認します。ループバックのscheme・portとCookie条件、登録・失効の手続は正本・受入の確認待ちです。[開発と移行の手順](app-architecture.md)を参照してください。

役割メールの提供状況は未確認のため、この文書では受付メールを案内していません。

## 受け取る情報

| 項目 | 確認する内容 |
| --- | --- |
| 基盤 | HTTPS origin、API版、有効な機能、表・列・行と操作の許可 |
| 認証サービス | issuer、audience、認証方式、scope、MFAの条件 |
| アプリ用クライアント | 登録済みclient_id、public / confidentialの種別、正確なredirect_uriとクライアント認証方式 |
| 管理権限 | アプリ登録・権限設定・service承認を行う管理者の条件 |
| 検証用の表 | collection、schema_version、許可された操作、架空の検証行 |
| 取込MCP | 管理サイトのHTTPS origin、アダプター版、利用可能な取込形式と実行主体 |
| メディア | 有効なcustody、store、外部原本の責任者、管理サイトのDropbox機能の有効化 |
| 顧客BFFのTLS | 公開認証局で検証できるCore・IdPのHTTPS入口。SSH転送・独自CA登録を端末の要件にしない |

## 公開Issueの依頼雛形

以下は公開してよい一般的な要件に置き換えて記入します。顧客名、実環境のorigin・戻り先、顧客の識別子・データは公開Issueに書かず、「非公開で交付希望」とします。origin / redirect_uriの正確な値は、登録前に環境管理者へ非公開で渡します。

```text
件名: アプリ用BFFの接続相談 / 用途

用途（顧客を特定しない説明）:
固定する仕様: API 0.7.0-experimental / 契約日 / 文書改訂
接続の主体: 人（OIDC） / service / 取込MCP
希望するクライアント種別: public（公開） / confidential（機密） / 要相談
アプリのorigin・redirect_uri: 説明用の値、または非公開で交付希望
開発端末: Mac等 / 利用ブラウザー
開発用redirect_uri: 希望scheme・ループバックhost・port・path（実値は非公開）
本番の固定HTTPS redirect_uri: 説明用の値、または非公開で交付希望
同一クライアントへの開発・本番URIの併存希望と期間:
移行完了・開発URI削除予定日、既存資格・セッション失効の確認:
公開CAのHTTPS入口、SSH転送・独自CA登録が不要な開発経路の交付希望:
MacのCookie条件、VPSの外部URL認識・秘密保管方式の確認事項:
利用するAPI・有効化を希望する機能:
表・列・行・操作の範囲（架空の識別子で説明）:
利用開始・終了予定:
管理者の権限設定・service承認の必要性:
メディア・Dropbox利用の要否と原本の責任分界:
検証用の架空データの希望:
未確定の点・確認したい点:
```

パスワード、トークン、秘密鍵、client_secret、Cookieは公開・非公開を問わずこの雛形に書きません。公開鍵も、管理者が指定した手順で交付します。

## 交付後の確認

HTTPS、API版、有効な機能、client_id、クライアント種別、登録済みredirect_uri、表・列・行の許可を照合します。仕様に載っていても環境にルートがあるとは限りません。[最初の読取](quickstart.md)と[本人の接続](authentication.md)、または[service接続](service-access.md)へ進みます。
