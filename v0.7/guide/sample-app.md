# 架空の業務メモアプリ

説明用の「業務メモ」を読む小さなアプリを例に、ブラウザー・BFF・Core APIの責任を確認します。名前、表、ID、値はすべて架空です。実際の顧客データや接続情報は含みません。

## 画面で行うこと

- 利用者がログインし、自分に見えるメモを一覧で読む。
- メモの表示名と値を、表の定義に従って表示する。
- 「権限がない」「取得できない」「行がない」を区別する。

## BFFで行うこと

1. [OIDC + PKCE](authentication.md)でログインし、stateと戻り先を検証する。
2. トークンをサーバー側で預かり、ブラウザーにはセッションcookieを渡す。
3. 表の一覧と定義を取得し、有効なcollectionとfield IDを確認する。
4. [query操作](../api.html)で許可された列と行を読み、画面用の応答に整える。

画面に渡す応答の例です。これは**架空アプリのBFFの応答**で、Core APIの応答schemaそのものではありません。

```json
{
  "items": [
    {"id": "demo-001", "title": "会議の準備", "state": "未着手"},
    {"id": "demo-002", "title": "資料の確認", "state": "完了"}
  ],
  "nextCursor": null
}
```

この例の `demo-001` をCore APIのUUID欄へそのまま送らないでください。実際のID、型、schema_version、cursorは取得した契約と応答を使用します。

## 更新を加えるとき

読取が成功した後で、検証用の表に更新を追加します。行のversionとschema_versionを保持し、同じ操作を再送するときは同じIdempotency-Keyと本文を使います。412なら再取得して差分を示し、利用者が操作を決め直します。通信断なら結果を確認してから復帰します。

完全なCore APIの要求・応答は[HTTP・実行例](examples.md)、仕組みは[競合・再送・復帰](reliability.md)、アプリ定義の登録は[アプリの登録と運用](tutorial.md)を参照してください。

## 無人処理やAIを追加するとき

定期処理には承認されたservice資格を使います。CSVをAIから取り込む場合は対象版の取込MCPアダプターを選び、差分計画の確認後に反映します。利用者の資格、service資格、取込キーを交換可能なものとして扱いません。
