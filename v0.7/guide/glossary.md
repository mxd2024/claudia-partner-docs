# 用語集

このガイドで使う用語の意味です。同じ概念には同じ呼び名を使い、APIの識別子や正式名称はそのまま記載します。HTTPの呼び出しは「リクエスト」、必要な条件は「要求する」、JWT assertionは「署名付きの要求」と区別します。

## 登場する人ともの

| 用語 | 意味 |
| --- | --- |
| 利用者（human） | 基盤にログインして、アプリやAIエージェントを使う人。基盤は、操作のたびに、その時点の権限とMFAを確認する |
| あなた（開発者） | このガイドを読み、アプリや処理を作る人 |
| 顧客アプリ | 顧客の業務に合わせて開発する、画面とサーバー側を持つアプリ。API上の`app`（アプリ定義）とは別 |
| 顧客アプリのサーバー側（BFF） | ブラウザーで使う顧客アプリが、トークンを預かるために持つ、サーバー側の部分 |
| service | 人の操作なしに動く処理（バッチや連携）。管理者の承認を受けた、表・列・操作・期限の範囲だけで動く |
| AIエージェント | 利用者を助けて、操作を行うもの。利用者の権限を超えられない |
| 基盤 | Claudia Partner 基盤。ログイン、権限、データ、メディア、アプリ定義を扱う共通サービス。このガイドが扱う共通のインフラを指す |
| API | プログラムがサービスを呼び出す入口の総称。基盤API、認証サービスのAPI、管理サイトの取込APIは、接続先と資格が異なる |
| 基盤API / CoreAPI | Claudia Partnerのデータと認可を扱うAPI。このガイドの「基盤API」はCoreAPIを指す。パスは`/v1`と`/v2`の系列 |
| 認証サービス（IdP） | 利用者のログインを担うサービス。OIDC（OpenID Connect）を使う |
| 組織の管理者 | あなたの組織で、利用者の権限を設定し、アプリ定義を登録し、serviceを承認する人。管理権限（`manage_access`と`service_administrator`の両方）と、MFAが必要。権限の付与は、環境管理者に依頼する |
| 環境管理者 | 利用環境の接続情報、有効機能、設定を管理する技術上の役割。担当する組織や人は、利用環境の取り決めによる |
| `manage_access` | アクセスの管理の権限（追加の管理面で判定する）。表を閲覧できる権利とは、別 |
| `service_administrator` | serviceの管理で、必須の、登録された管理者の条件 |
| 利用環境 | 基盤の接続先の単位。URL、有効な機能、稼働版、利用者が利用環境ごとに異なる。OSの開発環境や環境変数とは別 |
| 管理サイト | Claudia Partnerの管理サイト。「取込・出力」から、MCPの取込を行える |

## ログインと資格

| 用語 | 意味 |
| --- | --- |
| OIDC | ログインの標準の方式（OpenID Connect）。認証サービスが、利用者を確認する |
| PKCE | 認可コードを盗まれても使えないようにする仕組み。ログインのリクエストごとに、使い捨ての値を使う |
| SSO | Single Sign-On。認証サービスのログイン状態を使い、連携するアプリのログインをまとめる仕組み。使えるアプリと追加MFAの条件は利用環境の設定による |
| MFA | 多要素認証。パスワードに加えて、もう1つの確認を行う |
| アクセストークン | 基盤APIの呼び出しに付ける、有効期限のある資格 |
| リフレッシュトークン | アクセストークンを更新するための資格 |
| issuer | 認証サービスのURL（識別子） |
| client_id | 認証サービスに登録した、アプリを識別するID。環境管理者から受け取る |
| redirect_uri | ログインの後に、認証サービスが利用者を戻すURL。登録済みのものだけが使える |
| scope | トークンに求める、権限の種類 |
| 接続キー | MCPアダプターが管理サイトに接続するための、管理サイト用の資格。キー所有者の許可範囲で使う。人OIDCのトークンや基盤APIのservice JWTとは別 |
| provision / activate | serviceを使えるようにする手順。provisionで接続の情報を用意し、activateで有効にする |

## データ

| 用語 | 意味 |
| --- | --- |
| ケース / case | v2の`/v2/cases`で扱う単位。アプリが用途に合わせて使う。v1の`/v1/jobs`（ジョブ）とは別の契約 |
| 表 / collection | データを入れる表。collectionは、その識別子で、画面のラベルとは別 |
| definition | 表の定義（列と型）。`schema_version`は、その版 |
| version | 行や資格など、取得した対象そのものの版。更新の競合を検出するのに使う |
| revision | アプリや表の状態の変更の版（整数）。v2の検索や変更の監視が返す`revision`は、見えている行の集合の変更を表す、不透明な文字列で、数値として扱わない（大小の比較や、増分の計算をしない） |
| plan / fingerprint | 適用の前に作る、変更の差分と確認の対象。適用のときに、同じ計画かを照合する |
| アプリ定義 / `app` | 表、依存先、版を登録した、API上の単位。顧客アプリの実行プログラムや配置先とは別 |
| draft / committed | 表の保存の状態。ケースの業務の進み具合とは別 |
| 外部ストア | Dropboxなど、基盤とは別の原本の保存先。基盤が参照するには、利用環境での接続設定と対象への権限が必要 |
| custody | 画像の原本の保管の方式。`managed_original`（基盤が管理）と`external_reference`（外部の原本への参照） |
| policy / store | 画像の許可条件（policy）と、参照できる保存先の名前（store）。policyは、APIで取得する |

## 通信と再送

| 用語 | 意味 |
| --- | --- |
| リクエスト | クライアントがHTTPなどで送る呼び出し。仕様ファイルの「要求・応答」はリクエスト・応答を意味する |
| `Idempotency-Key` | 同じ操作の再送を見分けるキー。二重に実行されないようにする |
| `If-Match` | 操作が要求する、期待する版を指定するヘッダー |
| `request_id` | リクエストごとの識別子。問い合わせに添える |
| 結果不明（`OUTCOME_UNKNOWN`） | 操作が完了したか、確認できない状態。失敗とは限らない |

## AIエージェント

| 用語 | 意味 |
| --- | --- |
| MCP | AIエージェントが、ツールを呼び出すための、共通の接続方式 |
| MCPホスト | MCPのツールを呼び出す、AIエージェントのアプリケーション |
| MCPアダプター | 手元のPCで動き、AIエージェントのMCPを、管理サイトへの接続に変換するプログラム |
